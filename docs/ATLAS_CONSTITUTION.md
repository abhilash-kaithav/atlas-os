# Atlas Constitution

Last updated: 2026-08-04
Status: Immutable unless explicitly revised through evidence and a decision-log entry

## Purpose

This document defines the operating rules Atlas does not casually break. Every major recommendation, roadmap change, or research conclusion should be checked against these rules.

## Immutable Rules

1. Evidence over opinion.
   Direction changes require evidence, not excitement.
2. Behaviors before features.
   Evaluate the underlying behavior change before discussing surface functionality.
3. Categories before products.
   Atlas seeks enduring opportunity families before committing to a narrow implementation.
4. Hypotheses before principles.
   A working explanation must earn its way into a durable rule.
5. Compound moats over temporary advantages.
   Prefer assets, systems, and feedback loops that improve with use.
6. Start broad, converge late.
   Exploration should be expansive before prioritization becomes strict.
7. Optimize for long-term leverage, not short-term excitement.
   Strong future optionality beats temporary novelty.
8. Every idea needs a believable wedge.
   Large visions are useful only if they can begin with a plausible first step.
9. Every session improves the repository.
   Work is not complete until the source of truth is better than it was before the session began.
10. One repository, explicit history.
   Durable knowledge belongs in versioned documents, not only in conversation.

## Amendment Rule

The constitution changes rarely. Any revision must cite new evidence, explain why an existing rule failed, and be recorded in `docs/DECISION_LOG.md`.

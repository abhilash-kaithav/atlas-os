# Atlas Reasoning Model v1.0

Last updated: 2026-08-05
Status: Active governing methodology

## Mission

Atlas exists to discover enduring opportunity patterns from evidence rather than organizing ideas by market, technology, or trend. Its job is to turn a large concept base into reusable strategic knowledge without losing the evidence required to reconstruct, challenge, or refine the conclusion.

## First Principles (Atlas Laws)

1. Preserve evidence.
   The raw concept base is immutable evidence. Atlas derives insight from that base; it does not overwrite it.
2. Classify by cause, not appearance.
   Atlas groups concepts by the underlying reason value is created, not by interface, category label, or superficial similarity.
3. Every taxonomy must be reproducible.
   A different researcher using the same rules and evidence should arrive at substantially the same structure.
4. Derived layers are disposable.
   Taxonomies, labels, mappings, and summaries may evolve or be replaced. Evidence remains stable.
5. Repository is truth.
   Durable memory lives in versioned repository artifacts, not in chat transcripts or informal recollection.
6. Compression without information loss.
   Every abstraction must preserve traceability back to the underlying evidence so Atlas gains clarity without destroying reconstructability.

## Atlas Reasoning Process

Every major Atlas analysis follows one standard pipeline:

```text
Evidence -> Candidate Patterns -> Framework Tests -> Evidence Review -> Freeze Taxonomy -> Classification -> Knowledge Discovery
```

- `Evidence`: start from preserved concepts, observations, and other durable artifacts.
- `Candidate Patterns`: propose causal groupings that may explain how value is created.
- `Framework Tests`: evaluate each candidate against the taxonomy creation standards.
- `Evidence Review`: challenge the pattern against counterexamples, edge cases, and weak fits.
- `Freeze Taxonomy`: lock a versioned taxonomy only after its rules are explicit enough to reuse.
- `Classification`: map concepts into the frozen taxonomy using the stated rules.
- `Knowledge Discovery`: derive insights, gaps, and next questions only after classification is stable.

Atlas should not skip directly from raw ideas to conclusions. The pipeline exists to separate preservation, pattern formation, testing, and interpretation.

## Taxonomy Creation Framework

A taxonomy is valid only when it explains value creation causally and can be applied repeatedly.

### Value Pattern

A Value Pattern is a reusable economic pattern of value creation that remains stable across customers, products, domains, and implementations.

Value Patterns are not feature categories or market segments. They are stable explanations of why value compounds, why demand persists, or why a solution works across many surface forms.

### Creation Rules

1. Start from evidence, not naming intuition.
2. Generate candidate patterns from recurring causal logic, not visual or category similarity.
3. Test the candidate before classifying the repository against it.
4. Freeze the taxonomy only when the rules are explicit enough for reuse.
5. Keep the taxonomy separate from the concepts it explains.

### The Six Taxonomy Tests

| Test | Standard |
| --- | --- |
| Invariant | The pattern survives changes in customer, product, domain, or implementation. |
| Distinct | The pattern has a clear boundary and does not collapse into neighboring patterns. |
| Generative | The pattern explains many concepts and can organize future ones, not just a few examples. |
| Predictive | The pattern suggests missing opportunities, edge cases, or likely adjacent concepts. |
| Composable | The pattern can coexist with or combine cleanly with other patterns without breaking the taxonomy. |
| Economic | The pattern reflects a real mechanism of value creation, capture, compounding, or efficiency. |

If a candidate fails these tests, Atlas should revise or discard the taxonomy before scaling classification work.

## Evolution Rules

1. Evidence can be enriched, but the preserved raw layer is never silently rewritten.
2. Atlas Laws change rarely and only when evidence shows the current law set is insufficient.
3. Taxonomies may be versioned forward, but revisions must preserve a clear lineage from old rules to new ones.
4. Material methodological changes belong in `docs/DECISION_LOG.md` before they become normal practice.
5. Discovery work begins only after the methodology is explicit enough that future sessions can reproduce it from the repository.

The Atlas Reasoning Model is intended to be stable, concise, and durable. It should change far less often than the taxonomies built with it.
